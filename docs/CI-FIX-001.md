# CI-FIX-001: constrained scaled result panel

Diagnostic PR [#1](https://github.com/williamcampos-hue/Pauselith/pull/1) retained the original assertions. Run [44014242567](https://github.com/williamcampos-hue/Pauselith/actions/runs/44014242567) measured an interactive 96-DPI desktop of 1024×768, work area 1024×720. The initial partial/cancelled notices fit. After the harness's 150% programmatic scale, Windows constrained the form to 1044×788 (client 1028×749). Fixed and automatic result rows consumed more than the available height: row heights were **-37, 99, 150**, and the visible label's top was **-31**. Its 81-pixel wrapped text height was sufficient; its position was not. This is a real layout overflow triggered by constrained dimensions and synthetic scaling, not evidence of a noninteractive desktop or a text-height false positive.

The result card now scrolls its content-sized table instead of allocating a negative percentage row. Normal-size content and terminal messages remain reachable. The harness reveals controls through scrolling, retains its wrapped-height/no-ellipsis and immediate-parent assertions, and additionally checks the entire notice rectangle against every visible ancestor viewport. It forces the constrained dimensions locally before scaling, without changing desktop resolution. Measurements are retained in CI's text-only runner log even on success. No test is skipped, no dependency is updated, and audiovisual algorithms are unchanged.

Local and remote execution results are recorded in the PR and GitHub Actions. The earlier failed runs remain available as evidence; a diagnostic failure is not a passing validation.
